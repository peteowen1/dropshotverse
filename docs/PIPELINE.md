## Ratings refresh

Workflow: [`ratings-refresh.yml`](https://github.com/peteowen1/dropshotverse/blob/HEAD/.github/workflows/ratings-refresh.yml). Median wall time **2 min 45 s** (range 2 min 30 s to 3 min 17 s), from the first job starting to the last job ending, over the 5 run(s) listed below.

One job, once a day. It replays player Elo over the archived matches plus every tennismylife match since 25 May 2026, rebuilds ratings.parquet (and only that file: the locked pre-tournament predictions.parquet is not touched), checks it, and uploads it. Only scheduled runs from main are counted, and dry runs are not (they skip the upload).

**What starts it, and what it starts:** GitHub's own schedule, 06:00 UTC daily (about 5pm Sydney); GitHub's cron is best-effort, so recent runs have started anywhere from about 11pm to 4:30am Sydney (5 to 11 hours late). It can also be started by hand, with an optional dry-run box that builds and checks but does not upload.

## How to regenerate

```
python C:/dev/ops/scripts/pipeline_guide.py build --repo-dir <this repo>
```

It reads `docs/pipeline.json` (which workflows and jobs are the pipeline, one line per step) and the latest successful runs through `gh`, saves every response raw, and rewrites this file and `docs/pipeline-summary.json`. It fails if the config names a job, step or log pattern that no longer appears, so a renamed step cannot leave a stale description behind. Steps marked **(not confirmed)** were not checked against the script they run.
