# 01 — What historical tennis data actually survives?

Type: research
Status: resolved

## Question

Jeff Sackmann's bulk repos — `tennis_atp`, `tennis_wta`, `tennis_pointbypoint`, `tennis_slam_pointbypoint` — all return **404** as of 2026-08-27 (verified directly; the `JeffSackmann` user account and `tennis_MatchChartingProject` both still return 200, so this was deliberate removal, not account deletion). The obvious mirrors are useless: `jasonmauss/tennis_atp` was last pushed 2015-03-17 and `ppaulojr/tennis_wta` 2015-04-12.

**Where can a complete ATP + WTA + Challenger/ITF singles match-level dataset still be obtained, and how fresh and complete is each option?**

Chase, at minimum:
- Active forks of the dead repos with 2026 pushes (search the GitHub API by push date, and check fork networks — deleted-parent forks often survive with full history)
- Internet Archive / Software Heritage snapshots of the repos
- Zenodo, HuggingFace Datasets, and academic mirrors — Sackmann's data is widely used in published papers
- Kaggle, especially `dissfya/atp-tennis-2000-2023daily-pull` (claims daily updates to 2026) and `hakeem/atp-and-wta-tennis-data`
- `Tennismylife/TML-Database` (pushed 2026-01-27, ATP only) and its live successor at stats.tennismylife.org
- `mcekovic/uts-database` Docker image (ultimatetennisstatistics's pre-populated DB, ATP men only)
- Whether tennisabstract.com itself still serves anything bulk

**Deliverable:** a coverage matrix — source × tour (ATP/WTA/Challenger/ITF) × year range × granularity (match-level / point-level / shot-level) × freshness (last update) × licence × how to ingest programmatically. Then a ranked recommendation with the single biggest risk of each.

Be explicit about what is *missing* rather than glossing it. A source covering ATP 1968-2024 but no WTA is a different animal from one covering both to last week. Verify every claim by actually fetching, not by reading blog posts — most write-ups still describe the dead repos as live.

## Answer

Researched 2026-08-27. Every row below was fetched directly (GitHub API/raw content, Software Heritage API, Wayback CDX/availability API, Docker Hub API, live curl against data endpoints, or Kaggle JSON-LD metadata) — nothing here is taken from a blog post's word for it. Full commands and raw responses are reproducible; ask if you want the transcript.

### The headline finding

Jeff Sackmann's four bulk repos are gone, but the ATP-side data didn't actually vanish — it splintered into two live, independently-verifiable tracks, plus one frozen full-fidelity snapshot that dozens of ML projects silently re-vendored right before the takedown:

1. **A frozen "last known good" full-schema snapshot, cut ~2026-05-25** (right at Roland Garros), preserved verbatim (49-column Sackmann schema, all levels: tour/challenger/futures/qualifying/doubles/rankings/players, plus Slam point-by-point through 2024) in `Aneeshers/tennis-sackmann-archive` on GitHub *and* HuggingFace, and independently re-discovered as byte-identical copies vendored into at least half a dozen unrelated ML-prediction repos (`BackstageTalks/tbt-pro`, `halekevi/PropORACLE`, `ivanposinovec/ATP`, `michaelbruen/ATP_Tennis_Project`, etc.) — strong evidence this was the last successful automated pull before JeffSackmann pulled the repos, not one person's fabrication.
2. **A genuinely live successor, `stats.tennismylife.org`**, built by the same person behind the now-frozen `Tennismylife/TML-Database` GitHub repo (frozen 2026-01-27, stops mid-January). The live site serves the *same 49-ish-column schema* (player IDs, serve stats, everything) for ATP main tour + ATP Challenger + ATP qualifying, updated within 1-3 days (files timestamped 2026-08-24 to 2026-08-26 as of this writing, content running through the Cincinnati final). It also serves WTA **main tour only** (`2026_wta.csv`, current through 2026-08-13) — there is **no WTA challenger/ITF file anywhere on the site** (checked the full 171-file manifest at `/api/data-files`; the pattern is unambiguous — 49 `*_challenger.csv` files exist, all ATP, zero WTA equivalents).
3. **A separately-sourced live layer, `LuckyLoser91/TennisCourtLog`** (GitHub, updated via Actions, pushed as recently as yesterday), which is the freshest of everything found (through the actual Cincinnati final for both tours, 2026-08-24) but pays for it with a **13-column reduced schema** (no player IDs, no serve/ace/df stats, tour-level only — no challenger/futures/qualifying at all) sourced from `tennis-data.co.uk` from 2025 onward and stitched to players by a hand-maintained name-mapping file, not IDs.

### What is missing everywhere

- **No live source anywhere covers WTA Challenger/ITF-level matches.** This is a real, structural gap, not a freshness lag — TennisMyLife's site has 49 ATP challenger files and zero WTA equivalents; the frozen Aneeshers snapshot has WTA `qual_itf` files but only up to the same May-2026 freeze.
- **No live source has post-2024 point-by-point or shot-level data.** Slam point-by-point died (as a *maintained* dataset) in October 2024, over a year before the repos were actually taken down — the 2026 removal didn't cost anyone anything on this front that they hadn't already lost. `tennis_MatchChartingProject` is the only living shot-level source, and it's a curated volunteer subset, not comprehensive coverage.
- **No source combines full-schema (serve stats, player IDs) with true tour-wide freshness across both ATP and WTA at Challenger/ITF depth simultaneously.** You either get full schema + full depth but frozen at 2026-05-25 (Aneeshers/HF), or full schema + ATP depth live but WTA depth-limited (TennisMyLife), or true current-week freshness on both tours but a gutted schema and no depth below tour level (LuckyLoser91/tennis-data.co.uk).

### Ranked recommendation

1. **Base layer — `Aneeshers/tennis-sackmann-archive`** (GitHub, mirrored on HuggingFace). Use this for everything through 2026-05-25: full 49-column schema, both tours, all levels (tour/challenger/futures/qualifying/doubles), rankings, player bios, and Slam point-by-point through 2024. It's a plain git clone, no LFS, no auth, and its provenance is corroborated two independent ways (byte-identical to half a dozen other repos' vendored copies, and its stated upstream commit dates line up with Software Heritage's own crawl history). **Biggest risk:** it is a one-time human upload with no automation and no stated update plan — if that GitHub account or its HF mirror disappears, this exact frozen state has no other 1:1 copy with the full schema (the SWH snapshot is the fallback, but it is worse for WTA specifically, frozen 16 months earlier).
2. **Live layer for ATP (incl. Challenger/Qualifying) — `stats.tennismylife.org`'s `/api/data-files` endpoint.** Updated within 1-3 days, same rich schema as the base layer, and gives you the one thing nothing else does live: current-season ATP Challenger and Qualifying results. **Biggest risk:** the licence story is actively contradictory (site metadata says MIT, the maintainer's own README says research-only and warns the underlying data is ATP's) — treat this as "use for internal modeling, get explicit permission before anything redistributive," and note it's a single-maintainer hobby site with no SLA.
3. **Live layer for freshest possible tour-level score/rank data on both tours — `LuckyLoser91/TennisCourtLog`, or its upstream `tennis-data.co.uk` directly** if you don't need the repackaging. Use only to patch the gap between the Aneeshers freeze date and "now," and only for tour-level matches — there is no Challenger/ITF here at all. **Biggest risk:** no player IDs, so joining this layer against the base layer's player-ID-keyed history requires building and maintaining your own name-resolution/disambiguation logic (the repo's own `manual_mapping.csv` is a partial admission of how manual this already is), and it silently drops all serve/ace/df stats that many models depend on.
4. Treat Kaggle `dissfya/atp-tennis-2000-2023daily-pull` (updated yesterday, CC0, ATP-only) as a **licence-clean fallback/cross-check** for the tour-level ATP layer rather than a primary source, since its schema and row counts weren't verifiable without a Kaggle account in this environment. Treat Software Heritage as the archival/citable fallback if any GitHub-hosted source above disappears. Do not use `hakeem/atp-and-wta-tennis-data` (Kaggle, dead since 2020) or `mcekovic/uts-database` (Docker, dead since 2021) — both are exactly the kind of "described as live in old write-ups" trap the ticket flagged, and both were confirmed dead by direct timestamp checks in this research.
