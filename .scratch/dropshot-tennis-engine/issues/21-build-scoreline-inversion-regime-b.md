## Question

Ticket 12 established that per-match scoreline inversion is hopeless (a single 6-4 6-4 puts the MLE at the grid boundary) but a **panel** of ~150 sets from the same pool of players recovers the true serve/return split to within ±0.03 — feasibility proven, never built. Regime B (72.5% of the archive, scoreline-only) currently gets only a combined-strength update (ticket 20 hypothesis 2 also flags this path as under-tested for a different, more basic reason: even the combined-strength update's `n=1` evidence weighting is unvalidated).

Build the actual panel-based inversion: given a rolling panel of recent matches for a player-pool (or the update step re-derived to use the full Markov scoreline likelihood, not a Bradley-Terry `sigmoid(cw-cl)` proxy), does regime-B skill estimation improve — measured the same way as every other change this session (tune 2022-23, corruption-gated, reveal once on 2024-25)? This subsumes and should be attempted only *after* ticket 20's regime-B evidence-weighting question is answered, since a `REGIME_B_N` fix might already close much of the gap far more cheaply.

## Resolution (2026-08-28, round 7 of issue 20)

The cheap version of this ticket (real games-won-per-set counts fed into the existing `adf_update` as if `n` independent point-level trials) shipped earlier the same session and closed the gap from 0.0315→0.0114 (issue 20, round 3). This resolution covers the FULL version: the panel-based inversion described in the "Question" section above was superseded by a cheaper, equally-rigorous alternative that doesn't need a rolling panel at all — Bayesian filtering already provides the panel effect implicitly (each player's posterior accumulates evidence match-by-match, which is what a panel-based batch inversion would approximate anyway) — so the actual implementation follows the RESUME file's "concrete implementation idea" instead: use `p_set`'s own game-by-game DP to score the probability of the SPECIFIC observed set-by-set scoreline, and fit `d` against that richer per-match log-likelihood via a numerical Newton step, rather than building a separate rolling-panel MLE machinery.

**What was built** (`dropshotdata/scripts/hierarchical_model.py`, commit `a5222a5`):
- `p_set_full()` — exact refactor of `p_set`'s DP, returns the full terminal set-score distribution instead of collapsing to P(A wins). Verified bit-identical (stress test + a real fit-output diff, max delta 4.4e-16).
- `set_outcome_dist_for_d()` / `p_specific_set_score()` — the per-set-score likelihood as a function of the combined-strength gap `d`, under `p_a_serve=sigmoid(d/2)`, `p_b_serve=sigmoid(-d/2)` (the alpha=beta=c/2 split ticket 12 already established, made precise here since "symmetric" alone was ambiguous — the degenerate reading `p_a_serve==p_b_serve` would destroy all signal). Cached on a fixed 0.01-wide grid over `d∈[-12.5,12.5]`, not an unbounded structure, for bounded fit-time cost.
- `adf_update_full_dp()` — the Newton-step fit itself: central finite-difference grad/Hessian of the match's full log-likelihood, combined with the Gaussian prior via the same Laplace/ADF structure `adf_update` already uses.
- `parse_score_sets()` — per-set score parsing (vs. the existing lumped-sum `parse_score_games()`), rejecting DP-unrepresentable scores (old-rules undecided long deciders) with a whole-match fallback to the existing approximation.
- Gated behind `DSV_REGIME_B_FULL_DP` (default `"0"`, verified no-op). 9 new stress tests (`stress_test_safety.py` reproductions 6-14), all covering exactly the failure modes ticket 12 and this session's own hard-won lessons flagged: the refactor's correctness, extreme scorelines, the ticket-12 grid-boundary case, far-from-zero `d`, the symmetric-formula degeneracy trap, and cache boundedness.

**Result: tuned on 2022-23 (weighted/lopsided metric, `DSV_REGIME_B_N` re-scanned 0.1-4.0 under FULL_DP=1) — completely flat.** Best cell ties the v25 baseline within 0.0001 (noise, not a finding) on n=8,460 rows; weighted log-loss never leaves a 0.5758-0.5763 band across a 40x range of evidence weight. **Not revealed on holdout** (charter: only reveal a candidate you believe in; nothing here qualified). Full numbers, the corruption-gate behavior difference from the old approximation (N≥2.0 now passes cleanly, unlike before), and an operational incident (a tuning scan stalled silently and was recovered) are in `issues/20-why-does-hierarchical-lose-to-elo.md`'s round-7 section and `RESUME-beat-elo.md`.

**Why this is a real, informative negative result, not a wasted effort**: round 3 (third continuation) had already localized the aggregate defect to MC-posterior-averaging's Jensen's-gap convexity cost, downstream of the fitted mean state — and found the mean state itself already extremizes correctly. This ticket tested the complementary hypothesis (is regime-B's evidence extraction ALSO a bottleneck, upstream of that) directly, by giving the fit access to the full scoreline likelihood instead of a coarse approximation. The fitted state barely moved. That is strong confirmation the coarser evidence was already extracting what mattered — the ceiling is downstream of fitting (in how MC-averaging propagates uncertainty through the convex match-probability recursion), not upstream in evidence richness. Anyone revisiting this gap should look at the MC-averaging step itself, not at further regime-B evidence refinements — that avenue is now closed on real evidence, not assumption.

**Left in place, not reverted**: `DSV_REGIME_B_FULL_DP` and all the supporting code stay in `hierarchical_model.py` at their no-op default, in case a future fix to the downstream MC-averaging mechanism changes whether richer regime-B evidence matters. The stress tests are permanent additions regardless of this ticket's outcome (they guard real numerical-stability properties, e.g. the grid-boundary case, independent of whether the mechanism is ever turned on for production use).
