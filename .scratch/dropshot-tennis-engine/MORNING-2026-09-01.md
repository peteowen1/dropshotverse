## Discovery worth knowing about

**WTA has an open, unauthenticated live-scores API** (`api.wtatennis.com`),
covering US Open + WTA 500 + WTA 125 including `Serve`/`PointA`/`PointB`. This
overturns ticket 03's "WTA is walled" conclusion, which had shaped scope decisions
since 2026-08-27. Found by reading the site's own network traffic — you prompted
it by asking about the match centre.

**ATP genuinely is walled**: server-rendered Sitecore, no client API, and
`api.atptour.com` does not resolve. So the asymmetry is real but runs opposite to
what the project assumed.

## Push problem — found and fixed, nothing outstanding

Everything is pushed. `dev` is in sync with `origin/dev` at `27c582e`.

Worth reading anyway, because the failure mode was nasty: several pushes hung
with **no error message at all**, and it looked exactly like a credential prompt
blocking invisibly. It wasn't. `gh auth status` was healthy and `git ls-remote`
returned instantly, which ruled auth out.

The real cause: a `git add -A` of mine had swept the **137 MB
`sackmann_archive_raw.tar.gz` release-staging file** into a commit. GitHub hard-
rejects blobs over 100 MB, and the push stalled rather than reporting it. The
diagnostic that found it:

    git rev-list origin/dev..dev --objects | \
      git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)'

Fixed by soft-resetting the two unpushed commits, dropping the staging dir, and
adding `dropshotdata/tune_scratch/_release_stage/` to `.gitignore` so it cannot
recur. The Release assets were always meant to live in the Release, not git.

Lesson for me: `git add -A` in a repo that stages large build artifacts is a trap,
and a hanging push with no output means *check the pack size* before assuming
credentials.

## Two mistakes I made, both caught

Recording these because the *catching* is the reusable part.

1. **Attributed probability movements to the wrong cause.** I compared the locked
   forecast to the live one and narrated a story about rivals losing. That
   comparison conflates *learning the real draw* with *absorbing results*.
   Decomposing it (`--ignore-results`) reversed the headline: Sabalenka's +6.4 is
   +5.2 draw / +1.2 results; Tiafoe's rise is +2.6 draw / +0.2 results, not the
   Djokovic upset I claimed.
2. **Told you other verse releases were ~300x smaller than this one.** Wrong — I
   had sampled only the newest release per repo. pannadata alone holds 10.8 GB.
   You pushed back and you were right.

Also worth knowing: the entrants file's `slot` field is **not** draw position
(2/128 agreement with the real draw). Building on it would have produced a
completely wrong bracket that still looked plausible.
